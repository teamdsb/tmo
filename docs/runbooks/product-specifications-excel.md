# 商品规格与 Excel 导入导出

## 维护与购买

在 admin 商品列表打开商品编辑器。规格区域默认一级“规格”，可以添加至三级，并修改每层名称。每行是一个真实 SKU 组合，填写各级值、编码、启用状态与基础售价。删除末级后如果两个有效 SKU 变成相同组合，系统会指出冲突行，需要先调整组合再保存。重命名不会重建 SKU；删除 SKU 行会将原记录停用。

小程序详情和购物车换规格使用相同的逐级选择方式。上级未选不能选择下级，切换上级后需要重新选择后续值；只有实际有效组合可以加购。

## 模板与导出

在 admin 数据工作台下载中文维护模板，只接受 .xlsx。系统按表头定位数据工作表，允许表头前有标题；仅展开实际合并单元格，不把普通空白向下填充。标准表每行一个 SKU，同一商品使用相同“商品分组”（英文 Group Key）。模板附分类参考，业务字段置前，商品和 SKU ID 置后。旧英文模板继续可用。

数据工作台包含商品导入、商品导出和任务历史。导出当前筛选结果处理全部匹配页，也可以只导出待复核商品。来源商品的完整原始资料放在“来源资料”参考表；参考表不参与标准回导，维护时保留主表 ID。

新增列为 Product ID、SKU ID、Product Status、Spec 1 Name、Spec 1 Value、Spec 2 Name、Spec 2 Value、Spec 3 Name、Spec 3 Value。例如三级行填写“材质 / 钢、长度 / 20mm、直径 / M6”。同一商品各行的层级名称与顺序必须相同；后续级别可以整级留空，不得跳级。

保留 Group Key、Product Name、Category ID、SKU Code、SKU Name、Description、Cover Image、Images、Tags、Unit、Is Active、Price Tiers (Fen) 等原有列，并接受中文列名。Category ID 填真实分类 UUID；全零 UUID 表示待分类。Price Tiers (Fen) 示例为 1-9:1200|10-:1000，价格单位是分。空价格、图片、描述等可选字段默认保留已有值；需要清空时在预览展开该组，明确勾选对应清空操作。Attributes 支持 JSON 对象以完整保留包含分隔符的扩展属性；导出使用 JSON。Images、Tags 和 Filter Dimensions 同时接受 JSON 数组或原有竖线分隔格式。

旧文件可继续使用 Filter Dimensions 与 Attributes，或无维度的 Spec 列。六列显式规格和旧字段同时填写时必须一致，冲突会明确报错。Spec 是系统生成的完整路径摘要，修改名称/值时建议清空旧 Spec 和 Filter Dimensions，并同步移除 Attributes 中旧规格属性，保留扩展属性即可。

## 回导与错误处理

上传只识别和生成持久预览，不写入商品。核对新增、更新、跳过、独立创建以及警告后，点击确认导入。分类、单位、规格映射及分组可在预览修正，再保存重新校验；存在阻断错误时不能确认。确认使用预览版本和幂等键，其他管理员改动目标商品后必须刷新预览。任务历史和复核记录刷新后仍存在。

导出文件中的 Product ID 和 SKU ID 保持不变，系统优先按 ID 定位，再匹配 SKU Code。不要将现有 SKU ID 移到另一个商品；编码命中另一 SKU 时会拒绝。缺少 ID 和编码的新行会作为新 SKU，因此回导时保留导出 ID。重复导入原导出文件不会新增商品或 SKU。

Product Status 为 DRAFT、ACTIVE 或 INACTIVE。空状态在新建时默认 DRAFT，更新时保留已有状态。Is Active 控制 SKU 启用状态，与商品状态独立。无 SKU 商品导出商品行，其 SKU 字段全部留空，回导仍无 SKU。

导入不会删除文件中未列出的 SKU，但会检查最终所有有效 SKU 的组合。修改层级时应完整导出该商品后再编辑回导，避免未列出的 SKU 缺少新层级值。确认执行按商品组事务提交，组内失败不留下部分商品、价格、来源绑定或复核记录。全部成功、部分成功、失败和完成但待复核分别展示；任务中断仅恢复过期租约，已经提交的商品组不重复执行。

图片导出为原始 URL；本地图片仍可在 ZIP 中与 Excel 一起上传。导出不把图片转换成临时网关代理 URL。

## 母表与历史业务表

试运行母表关联“商品、SKU规格、独立属性、图片索引”，商品/SKU 编号作为稳定来源身份。最多三级，螺钉使用螺纹直径、长度、螺距；法兰使用公称通径、连接管外径；EPE 使用宽度、厚度、卷长。剩余属性和单位、依据、来源、SKU 图片关系保留在来源资料中，图片进入商品相册。销售价格、库存、销售单位等未知字段保持空，不用需求单位冒充销售承诺。

历史表识别“序号、物资、规格型号、单位、分类”。普通物资在归属明确时归组，完整型号可作为一级规格。纸箱三段尺寸必须带明确单位；620×600×340 不推定毫米，760×490×320m 不自动改单位。辅料等泛称、缺尺寸单位或规格歧义仅拆出异常行，每行形成一个单 SKU 草稿并提示复核。相同规格但不同来源 SKU 的碰撞行都独立处理，不以行顺序选择保留者；完全重复行跳过。

分类按完整路径唯一映射。缺失、不存在或有歧义时进入待分类并提醒，不自动猜测近似分类。非法 ID、编码归属冲突和非法价格继续阻断，不能通过新建草稿绕过。

同一来源重复上传、重排行序和修改文件名不增加商品，也不覆盖已经完成的人工修正。历史表没有稳定编号，去重使用原四个业务列；改变原始名称、规格、单位或分类可能视为新来源行，后续维护应导出带 ID 的标准文件回导。

## 持续复核

任务结果与商品列表显示待复核数量、原因及来源行。管理员在商品页修正分类、规格或单位后，明确标记已解决；普通保存不会清除提醒。待复核商品不能通过商品编辑或 Excel 回导上架。复核不要求补出价格，无价格仍沿用现有询价业务。

商品任务、预览、来源资料、商品复核和导出仅对 BOSS/ADMIN 开放，物流入口的页面访问权限不代表商品权限。

## 验证

后端运行 go test ./...（services/commerce 目录），数据库集成需要 COMMERCE_DB_DSN 指向独立测试库；测试会清理业务表，不能使用生产库。admin 的 product-specs.mock.spec.ts 覆盖三级编辑与 mock 导出回导，小程序商品详情与购物车 Jest 测试覆盖逐级选择。异步商品导出使用 POST /admin/products/export-jobs，GET /admin/import-jobs/{jobId} 查询状态和结果下载地址。

真实母表验收可通过 TMO_TRIAL_MASTER_WORKBOOK 和 TMO_TRIAL_IMAGE_ROOT 指向本机只读源文件与商品包根目录。对应测试验证 10 商品、42 SKU、325 属性、12 张图和重复导入。历史 1110 行原文件当前不可访问，只验证已保留真实样例，不能用合成数量测试替代完整原文件验收。
